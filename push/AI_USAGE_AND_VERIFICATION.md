> 记录截至 **2026-10-20**（北京时间）。整理依据：本仓库的源码、测试与公开文档，以及候选人留存的内部交接与排查记录（`docs/HANDOFF.md`、`docs/人机操作.md`、`docs/解决文档.md`——这三份含部署与协作背景，已被 `.gitignore` 排除，**不随公开仓库交付**；本材料已将关键事实内联，评委无需访问它们）。

> **责任划分先说清**：AI 辅助设计、编写代码、排查故障与撰写文档；**候选人负责需求取舍、金融口径、凭据与云资源授权、环境部署、真实操作验收、最终提交**。下表"候选人修正"指候选人在协作中提出问题、否决结果、要求重做或确认边界，**不虚构逐行手写代码，也不虚构未留存的评审签名**。

## 1. 使用了哪些 AI 工具

| 工具 / 方式 | 在项目里的实际用途 | 如何验证 |
|---|---|---|
| **AI 编程助手（本项目协作会话）** | 读题与拆解、架构与里程碑排期、编写 FastAPI/Next.js 代码与测试、读报错与 Trace 排障、撰写交付文档。具体客户端产品名称未留存，**不臆称**。 | 候选人对每次产出做：跑测试/构建、看真实接口返回、开页面核对；纠偏过程见 §4。 |

## 3. 候选人实际承担了哪些工作（无法由 AI 代劳的部分）

按内部操作手册的四道**决策闸门**推进，每一道都由候选人放行：

| 闸门 | 候选人做的事 | 放行证据 |
|---|---|---|
| **A. 选择交付形态** | 决定云厂商与主机、域名/端口、预算、对外访问方式；决定用 Mock 演示还是用已授权的真实数据；决定目标仓库与目录方案 | 公网 `8.136.108.32:3000` / `:8000` 可访问 |
| **B. 整理仓库** | 决定提交哪些文件、审查来源与版权、处理凭据泄露风险、确认 `.gitignore` 覆盖范围 | 公开仓库可访问且无密钥/数据库 |
| **C. 云端部署** | 开通主机、配置受限环境变量（扶摇 Key / 模型 Key / iFinD 令牌 / `MOCK_DATA_MODE=false` / `NEXT_PUBLIC_API_BASE`）、起前后端、重启以加载新代码、处理端口与依赖 | `/api/health` 返回 `env=prod`、`mock_data_mode=false`、`llm_configured=true` |
| **D. 发布与验收** | 亲手在**云端浏览器**里发起研究、看计划/工具/证据/产物、判断金融口径是否成立、判断合规文案是否越界、决定是否发布与录屏 | 云端 5 条真实操作线程（见 §5） |

候选人具体承担、且不属于 AI 决策范围的事项：

1. **凭据与安全**：凭据从哪里来、谁能用、如何注入、如何撤销。协作过程曾出现 GitHub PAT，候选人按手册要求**手动撤销并改用最小权限方式**；AI 全程未在文档、脚本、命令中写入任何令牌或从仓库读取密钥。
2. **数据授权判断**：扶摇/iFinD 数据能否公开演示、哪些原始响应不能作为"验收证据"公开、Mock 只保留构造样本。
3. **金融口径判断**（最关键的一条）：**利润表"营业收入总量"不能等同于"产品/业务分部收入"**；只有两年样本不能声称"三年趋势"；晚于证据时点的披露不能倒推"当时已知"。这条判断直接决定了产品在"收入架构变化"类目标上必须**承认能力缺口**，而不是给一个漂亮结论。
4. **环境事实核对**：本地/云端数据库、进程、`.env` 相互独立；改代码后不重启后端就不会生效；云端端口、持久化路径、代理行为由候选人实际确认。
5. **最终验收与提交**：录制 60–180 秒演示视频、决定提交链接、确认仓库同步状态。

> 一句话概括分工：**AI 把机制与代码写到可运行、可测试；候选人决定"什么才算对"。**

## 4. 候选人修正了哪些错误或不合理结果

以下每一条都是候选人先提出"这个结果不可接受/这个判断不对"，再定位、修复、回归。**"仍存边界"一栏是诚实交代，不是已解决项。**

| # | 候选人指出的问题（为什么不可接受） | 根因 | 怎么修的 | 验证与仍存边界 |
|---|---|---|---|---|
| 1 | **每次真实模型调用都被 HTTP 400 拒绝**。把模板降级说成"真实模型研究"属于误导评委会。 | 请求体固定 `response_format={"type":"json_schema"}`，该兼容端点不支持 | `json_schema → json_object → none` 逐级降档，成功档位按 `provider:model` 进程内记忆；把误导的 `attempts` 改为 `attempts_made` | `app/harness/model_router.py` + `tests/test_m1_router.py`；历史真实 E2E 10 次成功无 400（内部记录）。**不保证所有兼容端点都支持**。 |
| 2 | **推理模型只看到工具名，参数名靠猜且全错**：任务"计划了"却取不到数。 | 提示词未注入工具入参契约 | 注入工具 schema、校验入参、把错误回灌重试；离线时按受控契约保守兜底 | `tests/test_m1_tools.py`、`test_m2_tools.py`；**禁止猜出不存在的证券代码**。 |
| 3 | **研究目标是"近三年收入架构变化"，计划却去查行情/热榜**；且仅两年 Mock 利润表无法回答三年结构。 | 规划器兜底模板只有行情/热度类任务；工具集缺财报能力 | 补 `get_financials`（数据工具 8 → 9），规划与研究文本改为财报优先；缺年、缺分部、总量≠结构写入不确定层 | `tests/test_m5_api.py` + 前端 `lib/format.ts`。**真实数据也只有总量，仍缺三年分部附注**。 |
| 4 | **右侧研究产物全 0、证据卡被降级、引用只是一串内部 ID**。 | SSE `artifact` 帧只带 `artifact_id`，前端当完整产物渲染；`unit=null` 被判为"缺必填 prop" | 收到 `artifact` 帧后回查 `GET /api/runs/{id}/artifacts` 取 `latest`；统一契约"仅 `undefined` 算缺字段，`null` 合法显示为 `—`"；引用映射为证据序号+标题+原字段 | `tests/test_m5_api.py`、`test_m5_artifacts_ui.py`、`/selftest` 构建断言。**自测 ≠ 完整浏览器 Run**。 |
| 5 | **计划卡把 API 路径当工具名，甚至把"未调用"写成"无数据"**。这种展示会直接误导评委。 | 前端用 `ev.interface`（`/api/...`）作键去匹配计划里的工具名；未读 `tool_calls` | 证据接口补 `tool_name`（按 `tool_call_id` 回查）与 `tool_calls`；计划卡按 `task_id + tool_name` 分四种状态显示：未调用 / 调用失败 / 已调用但无证据 / 取到 N 条证据 | `web/skeleton/lib/format.ts` + 后端回归。 |
| 6 | **查询宁德时代却出现贵州茅台**；甚至模型借用无关证据的代码。候选人要求核实真实取数，而不是美化界面。 | 有真实 Key 仍 `MOCK_DATA_MODE=true`；Mock 检索忽略查询词；`_known_thscodes()` 从任意证据取第一个代码 | 缺省 `mock_data_mode=false`；Mock 与真实检索都按查询词过滤；带 `thscode` 的财报/快照/估值只保留请求代码；Agent 只认目标显式代码或唯一匹配的检索结果，未匹配即降级 | `tests/test_m2_tools.py`；受控真实探针命中 `300750.SZ`、4 期年报 2022–2025 且代码全匹配（内部记录）。**不得据其它公司生成目标结论**。 |
| 7 | **MCP 客户端装了 ≠ 业务在调用**：资讯任务实际拿的是市场热榜；首次真实调用还报缺 `time_start`。 | 工具蓝图未配置 iFinD 映射；应用未配齐 endpoint/key；`search_news/search_notice` 有四类必填参数 | `get_news_flash` 增加可选 `query`：已配置 MCP 时走 `search_news`/`search_notice`，按实时 `tools/list` 补 `query/size/time_start/time_end`（3 年时间窗、`size=5`）；未配置时直接报缺口，不拿热榜冒充公司公告 | 独立 iFinD 调用返回含目标文本（内部记录）。**一次完整 LLM Run 内同时完成 MCP 取证仍缺证据**；云端当前还有 `2003 401`。 |
| 8 | **`cost_total=0` 被误判为"没有调用 LLM"**（第一版分析文档写错了，候选人要求核对）。 | `model_router._http_complete` 把上游 `cost` 硬编码为 `0.0`，项目无价格表 | 新增 `cost_from_usage()` + `LLM_PRICE_INPUT/OUTPUT_PER_MTOK_CNY`（默认 0 = 不编造单价）；判据改为 `llm_calls>0 且 tokens_total>0 且 cost_total>0` 三者同时成立 | `tests/test_m1_router.py`。**云端仍未配单价，`cost_total=0` 只能用 tokens/llm_calls 佐证调用发生过**。 |
| 9 | **云端首页是占位页、API 基址退化成 `http:`，点"开始研究"直接 404**。第一版结论以为是"研究链路失败"，候选人要求先证明请求到底有没有打到后端。 | 前端 `resolveApiBase()` 只做"有值就用"，不校验完整性；`NEXT_PUBLIC_API_BASE=http:` 被原样拼进 `fetch()` | 首页 302/307 跳 `/console`；基址三段式校验（显式参数 / 环境变量 / 回退当前主机 `:8000`），坏值不传给 `fetch()`；新增构建期断言 | `web/skeleton/lib/sse.ts`、`app/page.tsx`；`/selftest` 断言增至 11 条。**HTTP/跨域/认证仍是部署侧问题**。 |
| 10 | **第一版产品"像 Agent 调试台，不像研究工作台"**：事实模块写成 `mock / /api/... / 引用：884d3c...`，`[object Object]`、`raw_ref —`。 | 展示层直接暴露内部对象，没有做研究语义转译 | 证据面板改为"研究引用面板"：标题/摘要、`raw_ref` 可点链接、对象结构化渲染、财报按年+指标+数值+单位；新增"研究结论与核验说明"，逐年呈现公司代码/口径/单位/时点/来源/证据序号 | `ArtifactView.tsx`、`EvidenceTable.tsx`、`ConclusionCard.tsx`；`npm run build` 通过。 |

**候选人还做了三项否决**（不是修 bug，是拦需求）：拒绝引入重型框架替换自研 Harness；拒绝为通过演示而放宽"缺数据必须披露"的规则；拒绝把免费/未计价模型的 Run 描述成"零成本运行"。

## 6. 诚实声明

1. 本记录不虚构"逐行手写"、不虚构评审签名、不虚构未能留存的截图或回执。
2. 三类证据（自动化测试 / 组件构建自测 / 云端浏览器 E2E）**互不替代**；`/selftest` 通过不等于研究链路通过，`COMPLETED` 不等于研究问题已回答。
3. AI 的已知局限在本项目里真实发生过：模型会猜错工具参数、会把跨公司证据串起来、会被结构化输出格式卡住、会给出合法的错误代码。这些都由校验层、目标绑定与合规守卫兜住，而不是靠"相信模型"。
4. 密钥、令牌、私人持仓与受限原始数据从未写入本记录；公网入口为 HTTP 且无鉴权，只用于非敏感演示。
