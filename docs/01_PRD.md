> 对应题目：`投资XBuddy.md`（投资 X Buddy）
> 文档状态：设计稿（未开始编码）
> 时间约束：24 小时
> 数据源依据：[DATASOURCES.md](./DATASOURCES.md)（扶摇接口已核实；iFinD 已实测 36 工具可用，仅作降级备源）

---

## 0. 一句话定位

**把「一个研究目标」变成「一份带完整证据链、可复核、区分事实与推断的研究结论」，并且整个过程可暂停、可恢复、可审计。**

### 0.1 它是什么

一个面向个人投资者的 **AI 研究执行器（Research Agent）**。用户不需要自己找数据、拼指标，只需说清楚想研究什么，系统负责：规划任务 → 调用金融工具 → 管理上下文与长期状态 → 产出可验证成果 → 在关键节点请求用户确认。

### 0.2 它不是什么（合规红线，必须写进产品）

| 不做 | 原因 |
|---|---|
| 不输出确定性涨跌预测 | 统一规则明令禁止 |
| 不输出收益承诺 | 统一规则明令禁止 |
| 不输出直接买卖建议 | 统一规则明令禁止 |
| 不做行情终端 / 交易入口 | 不在题目范围 |
| 不替代用户做决策 | 定位是「研究助理」，人是决策者 |

## 1. 目标用户

### 1.1 主用户画像

**「有自主研究习惯、但被数据工程拖住的个人投资者 / 投研爱好者」**

- 具备基础金融概念（懂 PE、资金流、板块轮动、涨跌停的含义）
- 目前的工作方式：多个网站/终端之间来回切，手工复制粘贴到 Excel，凭经验形成判断
- 核心诉求：**要快，但更要「能说清楚这个结论是哪来的」**

### 1.2 用户痛点（产品要解决的四个问题）

| 痛点 | 现状 | 产品解法 |
|---|---|---|
| P1 数据获取碎片化 | 行情、财务、资金、新闻分散在不同终端 | 统一工具层，由 Agent 自主取数 |
| P2 结论不可追溯 | 看到「资金流出」但不知数据哪天、哪个口径 | **证据链**：每条结论挂回原始字段（来源/时点/单位/口径） |
| P3 长任务无状态 | 聊到一半断线，上下文丢失，要重来 | **检查点与恢复**：任何中断都能续跑 |
| P4 过程黑盒 | 不知道 AI 为什么这么判断 | **可观测性**：计划、每步工具调用、每次 LLM 决策全链路可见 |

### 1.3 非目标用户

- 需要毫秒级交易信号的量化交易者（本产品不做高频）
- 希望「直接告诉我买什么」的用户（本产品明确不给买卖建议）

## 2. 核心用户旅程（主链路）

### 2.1 正常路径

```
① 用户输入研究目标
   "帮我看看最近半导体板块的资金和消息面，是不是有异动"

② 系统生成计划（Planner）
   → 动态UI 渲染「计划卡片」：4 个任务 + 依赖关系
   → 若目标有歧义（"最近"是几天？），弹出「澄清卡片」追问

③ 用户在计划上确认 / 修改（HITL 审批点）
   → 可直接删掉某个任务、缩小时间范围

④ 系统执行（AgentLoop：Think → Act → Observe）
   → 每次工具调用实时产出「证据卡片」，SSE 流式推送到前端
   → 上下文超预算时自动压缩（证据下沉到记忆，上下文只保留引用）

⑤ 关键节点二次审批（可选配置）
   → 例如"是否消耗额外预算做深度财务分析？"

⑥ 产出研究成果（ArtifactBuilder）
   → 「结论卡片」严格分三层：事实 / 推断 / 不确定
   → 每条挂「引用清单」，可点击回溯到证据卡片

⑦ 用户继续研究（新 Run 复用同一线程）
   → 或开启新线程（复用长期记忆中的偏好）
```

### 2.2 异常分支（必须实现，是题目硬性要求）

| 异常 | 系统行为 |
|---|---|
| 工具调用失败（限流 4001 / 超时 5002 / 不可用 5003） | 指数退避重试 → 切换备源（扶摇 ↔ iFinD）→ 仍失败则**降级**：跳过该任务，产出「降级说明卡片」，任务标记 `DEGRADED` |
| 数据过期 | **继续使用但显式标注**：`as_of` + 延迟时长 + 「结论置信度已降低」 |
| 多源数据冲突 | **不静默选一个**：同时展示两个值，标注来源与口径差异，提示用户注意 |
| 模型调用失败 | ModelRouter 切换 provider → 全部失败则进入「降级研判」：只列已获证据，**不给结论** |
| 进程崩溃 / 用户中断 | 从最近检查点恢复，已完成的任务不重跑（幂等） |
| 模型死循环 | 停止规则命中（同工具同参数 3 次 / 连续 N 步无新证据）→ 强制终止并说明原因 |
| 输出触发合规红线 | Guard 拦截，替换为「合规提示卡片」，记录拦截原因 |

## 3. 领域模型（题目要求：线程/任务/证据/产物/动态UI 的映射）

### 3.1 七个领域实体

| 实体 | 定义 | 在投资研究流程中的位置 |
|---|---|---|
| **Thread（线程）** | 一次研究主题的会话容器，可包含多次 Run | 对应「一个研究课题」，如"半导体板块异动排查" |
| **Run（运行）** | 一次完整的执行尝试，可被中断/恢复 | 对应「一次研究执行」，中断后恢复即产生新 Run |
| **Task（任务）** | 计划中的可执行单元（DAG 节点） | 对应「一个取数/分析动作」，如"拉取半导体成分股近 5 日资金" |
| **Step（步骤）** | Task 内一次 ReAct 迭代（思考→工具→观察） | 对应「模型的一次推理 + 一次工具调用」 |
| **Evidence（证据）** | 原子事实，带来源/时点/单位/口径 | 对应「一条原始数据」，是**可追溯的最小单位** |
| **Artifact（产物）** | 交付给用户的成果 | 对应「研究结论」，分事实/推断/不确定三层 |
| **UIBlock（动态UI）** | 可渲染的界面单元，引用 Evidence/Artifact | 对应「用户看到的一切」 |

### 3.2 关系与映射图

```text
Thread (研究课题)
  └─ Run (执行尝试，可中断恢复)
       ├─ Plan ──> Task[] (DAG)
       │              └─ Step[] (ReAct 迭代)
       │                    ├─ ToolCall ──> Evidence[]
       │                    └─ Thought
       ├─ Evidence[] (证据池，可被多个 Artifact 引用)
       ├─ Artifact[] (研究结论，分三层)
       └─ UIBlock[]  (由 Plan/Evidence/Artifact 渲染而来)

映射到投资研究流程：
  研究目标 → 计划 → 取数执行 → 证据积累 → 研判产物 → 界面呈现
```

### 3.3 关键设计原则

1. **Evidence 是唯一事实来源**。Artifact 中的每一句「事实」必须挂 `evidence_id` 引用；没有引用的句子不允许出现在事实层。
2. **Artifact 三层隔离**。`facts[]` / `inferences[]` / `uncertainties[]` 三个数组物理隔离，前端分区渲染、配色不同、标签不同。
3. **状态外置**。Run 的所有状态变更写入检查点，内存态可随时重建。

## 4. 功能需求清单

> 每条需求给出「描述 + 验收标准」。验收标准即测试用例来源。

### FR-01 研究目标输入与澄清
- **描述**：用户在对话区输入自然语言研究目标；系统识别歧义（时间范围、标的范围、分析深度）并追问，而非猜测。
- **验收**：输入「看看半导体是不是有异动」→ 系统必须追问「时间范围」与「关注维度」，不得直接开跑。

### FR-02 计划生成与展示（可编辑）
- **描述**：Planner 将目标分解为 Task DAG，以「计划卡片」展示任务名、意图、依赖、预计工具。
- **验收**：计划必须可视化且可删除/收缩单个任务；修改后重新执行遵循新计划。

### FR-03 能力 / 工具注册
- **描述**：工具以**注册表**方式接入，声明 `name / description / JSON Schema / 数据域 / 幂等性 / 超时 / 成本 / 权限级 / phase`。新增工具不改主循环。
- **验收**：新增一个工具只需注册声明，AgentLoop 零改动；工具总数可查询。

### FR-04 上下文压缩
- **描述**：上下文超过预算阈值时自动压缩：历史 Step 摘要化，**Evidence 下沉到外部存储、上下文只保留引用**（证据不可被压缩丢失）。
- **验收**：压缩前后，Artifact 仍能解析出全部 evidence 引用；压缩事件在 Trace 中可见（before/after token）。

### FR-05 记忆（三层）
- **描述**：工作记忆（Run 内 Step 序列）/ 会话记忆（Thread 内结论与证据索引）/ 长期记忆（跨 Thread 的用户偏好与研究历史，语义检索）。
- **验收**：新开 Thread 时，长期记忆能召回历史研究偏好（如"用户偏好看资金面"）。

### FR-06 检查点与恢复
- **描述**：Run 状态变更以**事件溯源**方式持久化；任意中断后可从最近检查点恢复，已完成 Task 不重跑。
- **验收**：执行到第 3 个 Task 时杀掉进程 → 重启恢复 → 前 2 个 Task 不重复调用工具（可用 Trace 证明）。

### FR-07 权限与审批（HITL）
- **描述**：计划确认、高成本工具调用、产物发布前可配置为「需审批」；审批即「冻结运行中 Loop → 等用户点击 → 继续」。
- **验收**：审批期间刷新页面，运行状态仍在等待；审批通过后从中断点继续，上下文一致。

### FR-08 停止规则
- **描述**：步数上限、token 上限、成本上限、墙钟时间上限、死循环检测（同工具同参数重复）、无进展检测（连续 N 步无新增 Evidence）、用户中断、合规拦截。
- **验收**：构造死循环场景（工具反复返回相同结果）→ 系统在阈值内终止并说明命中哪条规则。

### FR-09 成本与时延控制
- **描述**：每次 LLM 调用记录 token / 成本 / 延迟；ModelRouter 支持多 provider、超时、熔断、健康降级。
- **验收**：主 provider 超时 → 自动切换备 provider 并在 Trace 标记 `failover`；Run 结束时给出成本汇总。

### FR-10 可观测性
- **描述**：Run 下建立 Span 树（Run → Plan → Task → LoopIteration → LLM/Tool/Compact），全部落库，前端可查。
- **验收**：任一结论都能在 Trace 中定位到「哪次工具调用产出的哪条证据」。

### FR-11 证据链与可追溯
- **描述**：每条 Evidence 记录 `source / interface / as_of / unit / caliber / raw_ref / value`；Artifact 通过引用关联。
- **验收**：结论中任一句「事实」均可一键回溯到 Evidence，并显示来源接口名与时点。

### FR-12 产物三层表达
- **描述**：Artifact 严格分为 `facts / inferences / uncertainties`，每层可挂引用与置信度；推断层必须给出「证伪/切换条件」。
- **验收**：不出现无引用的「事实」句；推断句必须带条件，否则 Guard 拦截。

### FR-13 动态 UI
- **描述**：模型只能从**组件白名单**中产出 UIBlock（含 JSON Schema 约束）；支持流式增量渲染；渲染失败降级为原始 JSON 展示。
- **验收**：人为构造非法 props → 前端显示降级卡片而非白屏；Trace 记录渲染失败。

### FR-14 失败降级与恢复
- **描述**：工具/模型/数据三类失败均有明确降级路径，且**降级必须对用户可见、可解释**（降级说明卡片）。
- **验收**：断开数据源 → 系统不崩溃、不静默产出"正常"结论，而是产出带降级说明的部分成果。

### FR-15 合规安检（Guard）
- **描述**：产物输出前做三类检查：①禁止预测涨跌/收益承诺/买卖建议；②事实无引用即拦截；③推断无切换条件即拦截。
- **验收**：向模型注入「建议买入」指令 → Guard 拦截并在 Trace 记录。

### FR-16 线程管理
- **描述**：支持多线程、线程重命名、继续研究（在同一 Thread 上发起新 Run）。
- **验收**：同一 Thread 连续两次 Run 能共享会话记忆。

## 5. AI 角色定义（题目要求：说明 AI 的角色）

产品内共 **6 个 AI 角色**，均由同一批大模型承担，但**提示词与输出契约隔离**：

| 角色 | 职责 | 输入 | 输出契约 | 边界（不许做什么） |
|---|---|---|---|---|
| **Clarifier** | 识别目标歧义并追问 | 用户目标 | 追问问题（结构化） | 不许猜测后直接开跑 |
| **Planner** | 目标 → Task DAG | 目标 + 可用工具清单 | 任务列表（JSON） | 不许规划出未注册的工具 |
| **Reasoner**（AgentLoop） | ReAct 决策：下一步做什么 | 上下文 + 工具 schema | 工具调用 / 完成信号 | 不许编造工具返回；不许跳过证据落库 |
| **Compactor** | 上下文压缩 | 历史 Step + 预算 | 摘要 + 保留引用 | 不许丢弃 Evidence 引用 |
| **Synthesizer** | 证据 → 三层研判 | Evidence 池 | Artifact（三层） | 不许输出预测/建议/无引用事实 |
| **Guard** | 输出合规安检 | 待发布 Artifact | 通过 / 拦截 + 原因 | 不许放行无引用事实 |

### 5.1 AI 在「开发过程」中的角色（题目要求：AI 使用与验证记录）

| 环节 | AI 参与 | 人参与 |
|---|---|---|
| 架构设计 | 提方案、写文档 | **决策与纠偏** |
| 代码实现 | 主要实现者 | 指导 + 修正错误 |
| 金融口径 | 按文档实现 | **校验指标口径与来源标注** |
| 合规审查 | 实现拦截逻辑 | **确认红线覆盖完整** |
| 测试 | 生成用例 | **补边界场景** |

## 6. 数据使用

### 6.1 数据源

| 数据源 | 定位 | 覆盖 | 鉴权 |
|---|---|---|---|
| **扶摇**（主） | 结构化事实源 | 行情快照/历史K线、除复权、财务报表、估值、指数与成分股、交易日历、涨跌停/热榜/异动/龙虎榜、资讯 | `X-api-key` |
| **iFinD MCP**（备源） | 宏观与语义检索补充；**仅作降级备源**（返回自然语言文本、无强类型 schema） | 宏观 EDB、政策、公告语义检索、跨市场 | MCP 密钥（已配置并自检通过） |

> 详细接口清单与字段口径见 [DATASOURCES.md](./DATASOURCES.md)。

### 6.2 数据使用原则（硬约束）

1. **标的一律用完整 `thscode`**（如 `600519.SH`），不使用纯 ticker。
2. **时间一律记录毫秒级 Unix 时间戳 + `Asia/Shanghai` 语义**，展示时转可读格式。
3. **价格类字段带 `currency`**（A 股恒为 `CNY`）。
4. **涨跌幅为百分数原值**（`1.74` = +1.74%），不得二次乘 100。
5. **`null` 表示未披露/上游缺失，透传不补零**——不得用 0 顶替，必须在 UI 标注缺失。
6. **限流（HTTP 429 / `code=4001`）**：降并发、退避重试，不得立即连续重试。

### 6.3 数据质量元数据（贯穿全链路）

每条 Evidence 必须携带：

```json
{
  "source": "fuyao",
  "interface": "/api/a-share/prices/snapshot",
  "as_of": 1760000000000,
  "fetched_at": 1760000012345,
  "staleness_ms": 12345,
  "unit": "CNY",
  "caliber": "前复权/未复权/收盘价",
  "confidence": "normal | degraded",
  "degrade_reason": null
}
```

## 7. 合规边界（统一规则逐条落地）

| 统一规则 | 产品落地 |
|---|---|
| 不得输出确定性涨跌预测 | Guard 关键词 + 结构化校验双重拦截 |
| 不得收益承诺 | 同上 |
| 不得直接买卖建议 | 同上；产物模板中无「操作建议」字段 |
| 事实/推断/不确定必须区分 | Artifact 三层数组物理隔离 + 前端分区渲染 |
| 核心结论可回到原始字段 | Evidence 双向引用 + 一键回溯 UI |
| 明确来源、时点、单位、统计口径 | Evidence 强制字段（见 6.3） |
| 数据缺失/冲突/过期/失败**不得静默生成正常结论** | 四类异常均有显式状态与「降级说明卡片」 |
| 不提交 API Key / 隐私数据 | Key 走环境变量；用户持仓等一律构造数据 |

## 8. 已知边界

1. **市场范围**：以 A 股与指数为主；跨市场/宏观依赖 iFinD（已实测可用，但仅作降级备源），不可用时相关任务降级并显式标注。
2. **数据频率**：以快照 + 日级为主，不做盘中毫秒级。
3. **不做回测**：给出的不是策略收益验证，而是现状研判。
4. **单用户单租户**：不做多租户权限体系。
5. **iFinD 定位**：已实测 36 个工具可用（见 [DATASOURCES.md](./DATASOURCES.md) §3）；因其返回自然语言文本、无强类型 schema，**仅作降级备源，不承担主链路**。
6. **模型能力边界**：依赖外部 LLM，存在幻觉风险，故用「引用强制」与「Guard」两道闸兜底。

## 9. 未做事项（明确声明）

- 不做实时行情推送 / 消息通知
- 不做自动交易或券商对接
- 不做多轮长期驻留的后台任务（本产品是「按需研究」，不是 7×24 监控）
- 不做用户画像与个性化推荐
- 不做自然语言 → SQL 的通用数据查询
- 不做多模态（图表识别、语音）
